# 평가자 안내·정량 설문·불일치 협의 절차

자료 상태: 실제 평가 입력용 지침. 가상 평가 예제는 별도이며 자격 또는 평가 수행 사실을 주장하지 않는다.

## 1. 평가자 구성
A는 민원·상표 상담 실무자, B는 변리사 또는 상표 상담 경험자로 실제 참여자를 지정한다. 다수결을 쓰면 A·B와 다른 제3평가자 C(실무자, 변리사 또는 상담 경험자)를 미리 지정한다. 소속·직무·경력·자격 확인 방법과 평가일을 기록하고 서명한다. A와 B는 서로 다른 사람이어야 한다. 추천 시스템 개발자가 전문가 평가자를 가상으로 대체한 결과는 공식 평가가 아니다.

## 2. 성공과 실패
고객 질문의 의도와 단계에 맞고, 법적 설명이 정확하며 필요한 조건과 제한을 빠뜨리지 않고, 확인하지 않은 사건 사실이나 결과를 만들어내지 않으며, 추가 문구 수정 없이 상담 답변으로 사용 가능할 때 success이다. 내용 추가·삭제·수정, 잘못된 절차·금액·기한, 핵심 질문 누락, 근거 없는 단정이 필요하면 failure이다.

자료가 부족한 질문에 필요한 자료를 구체적으로 요청하는 적절한 응답은 성공일 수 있다. 반대로 충분한 정보로 답할 수 있는데 일반적인 주의 문구만 제시하는 회피 응답은 실패로 판단할 수 있다. 수수료 질문에 최신 금액을 검증하지 않고 숫자를 만들어내는 응답은 실패이다. 금액을 원한 구체적 질의에 확인 안내만으로 충분한지는 사전 승인된 성공기준으로 판단한다.

참고답변의 문구와 일치하는지가 아니라 추천된 원문 전체를 검토한다. 기대 템플릿 검색 여부는 별도 기계 진단이고 성공 판정을 자동 결정하지 않는다. 두 가지 질문 중 하나만 답했다면 실패로 볼 수 있다.

## 3. 문항별 정량 설문
각 추천 응답에 다음 5항목을 1~5점으로 평가한다. 1 전혀 충족하지 않음, 2 대체로 미흡, 3 일부 충족·수정 필요, 4 대체로 충족, 5 완전히 충족.
- 문맥 적합성: 질문 의도, 고객 상황 및 사건 단계를 올바르게 반영했는가?
- 법적·사실 정확성: 근거와 적용 규정에 부합하고 금액·기한을 사실처럼 지어내지 않았는가?
- 완결성: 질문의 핵심과 필요한 조건·다음 행동을 충분히 설명하는가?
- 실무 활용성: 사람이 문장을 고치거나 사실을 보완하지 않고 사용할 수 있는가?
- 안전성과 표현: 결과를 과장·보장하거나 확인되지 않은 사실을 단정하지 않고 이해하기 쉽게 표현했는가?

설문 점수는 보조 결과이다. 평균이 높아도 핵심 법적 오류가 있으면 failure이다. 점수 평균을 성공 응답 수로 변환하지 않는다. 모든 문항에 판정 이유, 평가자 성명·역할·평가일시를 남긴다. 특히 실패는 오추천, 절차 혼동, 조건 누락, 사실 오류, 설명 부족, 추가 자료 요청 미흡 등을 구체적으로 적는다.

## 4. 독립 평가 운영
1. 담당자가 승인된 자료 및 추천 원문을 동결한다.
2. A와 B에게 자신의 별도 평가 파일만 제공한다. 서로의 판정을 보지 않고 100건을 평가한다.
3. 결과를 제출한 뒤 최초 판정을 잠그고 평가 원본을 보관한다.
4. 담당자가 A와 B의 최초 판정을 대조해 최초 합의율을 산출한다.
5. 불일치한 건만 기준답변·근거를 다시 확인해 협의하고 최종 성공/실패, 변경 이유, 참여자, 일시, 서명을 남긴다. 최초 판정은 수정하지 않는다.
6. 두 명이 합의하지 못하면 임의의 다수결로 처리하지 않는다. 미해결로 남기거나 사전 승인된 제3평가자 절차로 확정한다.

## 4-1. 불일치 처리 규칙 — 협의 또는 다수결 중 사전에 하나를 정한다
시험 요구사항은 ‘평가 불일치 시 다수결 또는 협의로 최종 판정 확정’이다. 어떤 규칙을 쓸지는 평가 시작 전에 정하고 data/approval.json의 approved_decision_rule에 기록한다. 평가 도중이나 결과를 본 뒤에 규칙을 바꾸지 않는다.

협의(consensus): A와 B가 불일치 건만 다시 검토해 최종 판정, 이유, 참여자, 일시, 서명을 협의결과 CSV에 남긴다.
```bash
python scripts/collect_ratings.py --run-dir <run> --a <A.xlsx> --b <B.xlsx> --resolution <협의.csv> --output <ratings.csv>
python -m nlu.cli score --run-dir <run> --ratings <ratings.csv> --decision-rule consensus --output <metrics.json>
```

다수결(majority): A·B와 다른 제3평가자 C가 불일치 건만 독립 판정한다. 세 판정 중 다수, 즉 C의 판정이 최종 판정이다. C에게는 A·B의 판정과 근거를 보여주지 않는다. 다수결 결과는 협의로 뒤집지 않는다.
```bash
python scripts/make_tiebreak_workbook.py --run-dir <run> --a <A.xlsx> --b <B.xlsx> --output 평가자C_실평가.xlsx
python scripts/collect_ratings.py --run-dir <run> --a <A.xlsx> --b <B.xlsx> --c 평가자C_실평가.xlsx --decision-rule majority --output <ratings.csv>
python -m nlu.cli score --run-dir <run> --ratings <ratings.csv> --decision-rule majority --output <metrics.json>
```
두 규칙 모두 합의율은 규칙 적용 전 최초 A=B 건수 ÷ 100이다. 3인 전원 평가를 하려면 C가 100건 모두 평가한 파일을 쓴다. 이때 집계에 3인 만장일치율, 쌍별 일치율, Fleiss κ가 보조 지표로 함께 나온다.

## 6. 모의 예제의 사용 제한
모의 A는 기대 템플릿 ID 일치 여부를 success/failure로 바꾸는 규칙이다. 모의 B는 같은 규칙에서 13의 배수 문항을 추가로 failure 처리한다. 불일치는 보수적으로 failure로 정하는 가상 협의 예제를 적용한다. 이는 계산·파일 흐름을 보여주기 위한 임의의 시뮬레이션이며 실무자·변리사의 판단, 실제 협의 또는 추천 응답 적합도의 측정이 아니다. 생성되는 수치는 목표 또는 합격 성적으로 제출할 수 없다.
