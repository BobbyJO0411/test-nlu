# 남은 작업 실행 로드맵 — 정식 시험까지

작성일: 2026-11-10. 개발 단계에서 준비된 도구를 기준으로, 정식 시험 성적 산출까지 사람이 수행해야 할 단계를 순서대로 정리한다. 각 단계의 완료 기록은 근거검토_및_제출체크리스트.md의 해당 항목에 체크한다.

## 0. 전체 순서
- 1~3단계는 동시에 진행할 수 있다.
- 4단계(실제 질의)는 3단계(템플릿 검토)가 끝난 뒤 정답 주석을 시작한다. 템플릿이 바뀌면 기대 템플릿 ID가 달라질 수 있기 때문이다.
- 5단계 승인 이후에는 질의·템플릿·대표 질문·검색 설정·모델을 바꾸지 않는다. 바꾸면 해시가 달라져 다시 승인받아야 한다.

## 1. 시험기관 확인 (담당: 시험 담당자)
- 입력: artifacts/review_package/시험기관_확인요청서.docx (14개 질문)
- 할 일: 발송하고 회신 문서 번호를 회신 기록란과 data/approval.json의 agency_model_acceptance_reference, sampling_approval_reference에 적는다.
- 회신에 따라 정할 것: 모델(KoE5 인정 여부), 하이브리드 검색 허용 여부(β), 실제 질의 필요 여부와 표본 방식, 협의/다수결 중 결정 규칙, 합의율 정의, 합격 기준.
- 하이브리드 불허 시: 개발셋에서 β=0으로 다시 튜닝한다. `python -m nlu.cli tune --beta 0 --write-config ...`
- 완료 조건: 위 여섯 가지가 문서로 확정됨.

## 2. 평가자 섭외 (담당: 시험 담당자)
- A: 민원·상표 상담 실무자, B: 변리사 또는 상표 상담 경험자. 서로 다른 사람이어야 한다.
- 다수결이면 제3평가자 C를 미리 지정한다. C는 A·B와 달라야 한다.
- 소속·직무·경력·자격 확인 방법을 기록한다(평가기준_설문_협의절차.md 5장 서명 양식).
- 완료 조건: 평가자 명단과 자격 확인 기록, 평가 일정 확정.

## 3. 템플릿 DB 전문가 검토 (담당: 실무자 또는 변리사)
- 입력: artifacts/review_package/템플릿DB_전문가검토.xlsx (템플릿 30개, 추가 대표질문 120개)
- 템플릿마다 approve / revise / remove, 대표질문마다 keep / revise / remove를 고르고 법령·기한 확인기준일과 검토자 정보를 적는다.
- 확인: `python scripts/apply_template_review.py --workbook <작성된 파일>` (파일을 바꾸지 않고 누락만 점검)
- 반영: `python scripts/apply_template_review.py --workbook <작성된 파일> --write`
- 수정이 있었다면: 개발셋으로 다시 튜닝하고, `python scripts/make_template_review_workbook.py`로 새 워크북을 만들어 수정 없는 확인 검토를 한 번 더 받는다.
- 템플릿 삭제는 자동 반영하지 않는다. 기대 템플릿 ID와 개발셋을 함께 고쳐야 하므로 개발자가 처리한다.
- 완료 조건: 모든 템플릿 approval_status=approved, 대표질문 파일 status=approved. 집계 시 template_items_approved=true.

## 4. 실제 고객 질의 100건 (담당: 상담 부서, 시험 담당자, 실무자)
- 입력 양식: artifacts/review_package/실질의_입력양식.csv (query 필수, category 권장, received_date·channel은 기록용)
- 원본 CSV는 저장소에 넣지 않는다.
- 익명화·층화 추출: `python scripts/prepare_real_queries.py --input <원본.csv> --output data/questions_holdout_candidate.json`
- 사람이 100건 전부 읽고 남은 개인정보를 지운다. possible_name_review 표시 건은 반드시 확인한다.
- 정답 주석(기대 템플릿 ID, 기준답변, 근거)을 주석 CSV에 작성하고 합친다: `python scripts/apply_annotations.py --questions data/questions_holdout_candidate.json --annotations <주석.csv> --output data/questions_holdout.json`
- 이 100건을 보고 템플릿·대표 질문·가중치를 고치지 않는다.
- 완료 조건: data/questions_holdout.json 100건, 익명화 검토 기록, 주석 검토자·일자 기록.

## 5. 승인과 동결 (담당: 승인권자)
- `python scripts/approval_hashes.py --questions data/questions_holdout.json --decision-rule <consensus|majority> --output data/approval.draft.json`
- 실제 서명 승인서를 작성하고 빈 항목을 채워 data/approval.json으로 저장한다(Git 제외).
- 완료 조건: approval.json의 해시가 현재 파일과 일치하고 결정 규칙이 기록됨.

## 6. 정식 실행 (담당: 시험 담당자)
- 커밋된 깨끗한 작업트리에서 실행한다.
- `python -m nlu.cli run --model-id nlpai-lab/KoE5 --model-path ../nlu-models/nlpai-lab__KoE5 --questions data/questions_holdout.json --dataset-type real_anonymized_holdout`
- `python scripts/build_deliverables.py --run-dir artifacts/runs/<run-id>`
- 완료 조건: manifest의 git_worktree_clean=true, 평가자A·B 파일 생성.

## 7. 독립 평가 (담당: 평가자 A, B)
- 각자 자신의 파일만 받아 100건을 success/failure로 판정하고, 5개 정량 설문(1~5점)과 판정 이유를 적는다.
- 서로의 판정을 보지 않는다. 제출 후 최초 판정은 수정하지 않는다.

## 8. 불일치 처리 (담당: A·B 또는 C)
- 협의: 불일치 건만 다시 검토해 최종 판정, 이유, 참여자, 일시, 서명을 협의결과 CSV에 남긴다.
- 다수결: `python scripts/make_tiebreak_workbook.py ...`로 C용 파일을 만들고, C가 불일치 건만 블라인드로 판정한다.

## 9. 집계 (담당: 시험 담당자)
- `python scripts/collect_ratings.py ...` 후 `python -m nlu.cli score ... --decision-rule <규칙>`
- 완료 조건: status=complete, submission_candidate=true. false이면 결과 JSON의 각 확인 항목(expert_approval_record_present, template_items_approved, evaluator_records_complete, questionnaire_complete, resolution_records_complete, agency_approval_record_present)에서 원인을 찾는다.

## 10. 성적서 작성 (담당: 시험 담당자)
- 시험성적서_작성양식.docx에 적합도(%), 합의율(%), FCr-1-G 값, 설문 통계, 불일치 처리 내역을 옮기고 증빙(서명 승인서, 평가 원본, 실행 manifest, 해시 목록)을 첨부한다.
- 개발 단계 자료(합성 100건 결과, 모의 평가, 개발셋 결과)는 실제 성적 증빙에 넣지 않는다.
