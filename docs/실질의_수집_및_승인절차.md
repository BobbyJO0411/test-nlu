# 실제 고객 질의 수집·익명화·정답셋 승인 절차

문서 상태: 운영 절차 초안. 작성일 2026-11-06. 이 절차의 각 단계는 실제 담당자가 수행하고 기록한다. 스크립트는 기계적인 처리만 돕고 사람의 검토나 승인을 대신하지 않는다.

## 1. 원천 자료 추출 (담당: 민원·상담 실무 부서)
1. 상담 시스템에서 기간을 정해 고객 질의 원문을 CSV로 내보낸다. 열 이름은 query, 유형 분류가 있으면 category를 쓴다.
2. 원본 CSV는 저장소에 넣지 않는다. 접근 권한이 있는 보관 위치에 두고 파일 해시만 기록한다.
3. 추출 기간, 채널, 건수, 담당자를 기록한다. 이 기간·채널이 실제 운영 분포를 대표하는지 시험기관의 확인을 받는다(docs/시험기관_확인요청서.md 질문 5~7).

## 2. 익명화와 표본 추출 (담당: 시험 담당자)
```bash
python scripts/prepare_real_queries.py --input <원본.csv> --output data/questions_holdout_candidate.json
```
- 이메일, URL, 주민등록번호, 카드번호, 상표 출원·등록번호, 사업자번호, 전화번호, 계좌번호를 자동으로 가린다.
- ‘홍길동님’처럼 이름으로 보이는 표현은 가리지 않고 possible_name_review로 표시한다. 사람이 반드시 확인한다.
- 같은 문장은 한 번만 남기고 너무 짧은 질의는 뺀다.
- category가 모두 있으면 실제 유형 비율에 비례해 100건을 층화 추출한다. 없으면 고정 시드로 단순 무작위 추출한다.
- 결과: 질의 파일, 주석 작성용 CSV(…_annotation.csv), 표본 추출 기록(…_sampling_manifest.json). 기록에는 원본 해시, 제외 건수, 배분, 시드가 남는다.
- 자동 익명화는 완전하지 않다. 담당자가 100건 전부를 읽고 남은 개인정보를 직접 지운 뒤 anonymization.manual_review를 기록한다.

## 3. 정답셋 주석 (담당: 실무자 또는 상담 경험자)
1. 주석 CSV에 각 질의의 기대 템플릿 ID(복수 가능), 기준답변, 근거 source_ids, 검토자, 검토일을 입력한다.
2. 어느 템플릿으로도 수정 없이 답할 수 없는 질의는 빼지 않는다. 기대 템플릿으로 T030(자료 부족 안내) 등 가장 가까운 것을 적고 의견란에 사유를 남긴다. 템플릿 DB의 공백도 시험 결과의 일부이다.
3. 주석을 합친다.
```bash
python scripts/apply_annotations.py --questions data/questions_holdout_candidate.json --annotations <주석.csv> --output data/questions_holdout.json
```

## 4. 사전 승인과 동결 (담당: 승인권자)
1. 승인 대상: 시험 질의 파일, 템플릿 DB(data/templates.json), 템플릿 대표 질문(data/template_queries.json), 검색 설정(data/retrieval_config.json), 모델 ID·커밋.
2. 현재 해시를 출력하고 승인서 초안을 만든다. 이름·역할·일시·서명 참조는 비워 둔다.
```bash
python scripts/approval_hashes.py --questions data/questions_holdout.json --output data/approval.draft.json
```
3. 승인권자가 실제 서명 승인서를 작성한 뒤 빈 항목을 채워 data/approval.json으로 저장한다. data/approval.json은 Git에 올리지 않는다(.gitignore).
4. 승인 후 위 파일을 하나라도 바꾸면 해시가 달라져 score 단계에서 expert_approval_record_present=false가 된다. 바꿨다면 다시 승인받는다.

## 5. 금지 사항
- 시험 질의(data/questions_holdout.json)를 보고 템플릿, 대표 질문, 검색 가중치를 고치지 않는다. 조정은 개발셋(data/dev_queries.json)이나 별도 수집분으로만 한다.
- 개발 중 이미 공개된 data/questions_100.json의 결과를 최종 성적으로 제출하지 않는다.
- 익명화 전 원문을 평가자 파일, 저장소, 외부 LLM 호출에 넣지 않는다.
