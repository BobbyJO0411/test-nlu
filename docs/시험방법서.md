# NLU 기반 반자동 응답 추천 기능 적합도 시험방법서

문서 상태: 자체 시험용. 작성 2026-10-14, 개정 2026-11-11(자체 시험 절차와 합격 기준 확정).

## 1. 시험 항목과 대상
- 시험 항목: NLU 기반 반자동 응답 추천 기능 적합도
- 시험 대상: 고객 질의를 한국어 E5 문장 임베딩(nlpai-lab/KoE5)으로 해석하여 사전 등록된 응답 템플릿 DB에서 응답 후보 상위 3개를 추출하고, 1순위 템플릿 원문을 추천하는 기능
- 사용 형태: 추천 응답을 상담자가 확인 후 사용하는 반자동 흐름

## 2. 측정 검증 방법
- 실무자 대상 정량 설문 결과 제출: 평가자는 100건 각각에 대해 문맥 적합성, 법적·사실 정확성, 완결성, 실무 활용성, 안전성과 표현 5개 항목을 1~5점으로 입력한다.
- 평가 불일치 시 다수결 또는 협의로 최종 판정 확정: 시험 시작 전에 둘 중 하나를 정한다.
  - 협의: 평가자 A·B가 불일치 건만 다시 검토해 최종 판정, 사유, 일자, 참여자를 기록한다.
  - 다수결: A·B와 다른 제3평가자 C가 불일치 건만 판정하고, 세 판정 중 다수를 최종 판정으로 한다.

## 3. 측정 방법
- 실사용 환경을 반영한 고객 질의 100건을 기반으로 자동 추천된 응답 결과를 수집한다.
- 각 응답 결과에 대해 실무자 또는 평가자(변리사 또는 고객 상담자)가 추천 응답이 실제로 문맥에 적합한지 평가한다.
- 적절한 응답으로 수정 없이 활용 가능한 경우 ‘성공’, 불완전하거나 수정이 필요한 경우 ‘실패’로 간주하여 적합도(%)를 산출한다.
- 평가자 A·B는 서로 다른 사람이며, 상대의 판정을 보지 않고 독립적으로 평가한다.

## 4. 측정 환경
- 테스트 질의는 민원 유형에 따라 다양한 주제와 문장 구조를 포함하도록 구성한다: 상표 민원 25개 유형(등록 절차, 거절 이유, 수수료 등) × 4건, 문장 구조 4종(상담형, 절차확인형, 오해·경계조건형, 구어·상황형) 각 25건. 파일: data/questions_100.json
- 정답셋은 민원 대응 실무자 또는 상담 경험자에 의해 사전 검토 및 승인한다. 승인 기록은 data/approval.json(검토자, 역할, 승인일, 질의·템플릿 해시)에 남기며 시험결과서에 표시된다.
- 추천 응답 후보는 사전 등록된 응답 템플릿 DB에서 추출한다: 템플릿 30개(data/templates.json)와 템플릿별 대표 질문(data/template_queries.json).
- 객관적인 문맥 적합성 확보를 위해 합의율을 산출한다.

## 5. 실행 환경
- 모델: nlpai-lab/KoE5(E5-Ko 기반 문장 임베딩 모델, intfloat/multilingual-e5-large 한국어 미세조정, 1024차원, 커밋 237b580aea358e3042fcf5baf78124c33c3afd16). 모델 파일은 공개 해시와 대조한 뒤 사용한다.
- 검색: α × (질의와 대표 질문 간 최대 코사인 유사도) + (1−α) × (질의와 템플릿 본문 코사인 유사도) + β × (문자 n-gram 유사도), α=0.75, β=0.3. 가중치는 시험 질의와 분리된 개발셋 90건(data/dev_queries.json)에서만 정했다.
- 지표 산출: ISO 기준 산정식 적용 후 백분율로 결과를 표시한다.
- 하드웨어·OS·Python·라이브러리 버전과 소스 커밋, 파일 해시는 실행 시 manifest.json에 자동 기록되고 시험결과서에 표시된다.

## 6. 측정 지표
- 측정 지표: ISO/IEC 25023:2016, 8.2.2 Functional correctness measures (FCr-1-G: Functional correctness)
- 적합도(%) = (성공 응답 수 ÷ 전체 응답 수) × 100
- 합의율(%) = (합의 응답 수 ÷ 전체 응답 수) × 100. 합의 응답 수는 불일치 처리 전 평가자 A·B의 최초 판정이 일치한 건수이다.
- FCr-1-G: X = 1 − A/B (A: 최종 실패 응답 수, B: 평가한 전체 응답 수). 적합도와 같은 값이다.
- 보조 지표: Cohen κ, 적합도 Wilson 95% 구간, 유형별 성공·실패, 설문 항목별 평균과 분포.

## 7. 합격 기준
- 적합도 80% 이상이면 합격, 80% 미만이면 불합격으로 판정한다.
- 100건 모두 최종 판정이 확정되지 않으면 적합도를 산출하지 않고 ‘판정 불가’로 표시한다. 미평가 건을 분모에서 빼지 않는다.

## 8. 시험 절차
아래 python은 NLU 가상환경의 Python이다(Windows: ..\nlu-venv\Scripts\python.exe).

1. 실행과 평가지 생성: 커밋된 깨끗한 작업트리에서 실행한다.
```
python scripts/self_test.py prepare
```
결과 폴더 artifacts/self_test/<실행ID>/에 manifest.json, recommendations.json, 평가자A.xlsx, 평가자B.xlsx, 실행요약.json이 만들어진다.

2. 독립 평가: 평가자A.xlsx, 평가자B.xlsx를 각 평가자에게 따로 전달한다. 평가자는 100건 모두 판정(success/failure), 설문 5개, 평가근거, 성명, 역할·자격, 평가일시를 입력한다.

3. 불일치 정리:
```
python scripts/self_test.py resolve --run-dir artifacts/self_test/<실행ID> --a <평가자A.xlsx> --b <평가자B.xlsx>
```
협의이면 협의결과.csv가 만들어지고, 불일치 건의 final, resolution_reason, resolution_date, participants를 채운다. 다수결이면 `--decision-rule majority`를 붙여 평가자C.xlsx를 만들고 제3평가자가 작성한다.

4. 집계와 판정:
```
python scripts/self_test.py score --run-dir artifacts/self_test/<실행ID> --a <평가자A.xlsx> --b <평가자B.xlsx>
```
다수결이면 `--decision-rule majority`를 붙인다. 결과 폴더에 시험결과서.docx, 시험결과_상세.xlsx, 시험결과.json, ratings.csv가 만들어진다.

## 9. 무결성
- 평가 파일의 실행ID와 추천 결과 해시가 실행 기록과 다르거나, 질의·추천 원문이 바뀌었거나, 판정·설문·평가자 정보가 하나라도 비어 있으면 집계하지 않는다.
- A와 B가 같은 사람이면 집계하지 않는다. 다수결의 C는 A·B와 달라야 한다.
- 최초 판정은 협의 후에도 덮어쓰지 않으며, 합의율은 최초 판정으로 계산한다.
- 시험 결과 폴더 전체(평가 원본 포함)를 보관한다.
