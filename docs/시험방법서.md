# NLU 기반 반자동 응답 추천 기능 적합도 시험방법서

문서 상태: 사전 검토용 초안. 작성일 2026-10-14. 실제 시험기관의 성적서 또는 인증서가 아니다.

## 1. 목적과 시험 대상
사용자 시험계획의 ‘NLU 기반 반자동 응답 추천 기능 적합도’를 검증하기 위한 절차이다. E5 문장 임베딩으로 사전 등록된 30개 응답 템플릿을 검색하고 고객 질의에 대한 추천 원문을 표시하는 기능을 대상으로 한다. 상표의 등록 가능성 자체를 확정하는 법률판단 도구가 아니다. 사람이 추천을 검토하고 전송하는 반자동 사용 흐름이다.

현재 저장소는 독립된 추천·시험 모듈이다. 기존 제품 백엔드 연결이나 운영 고객 상담 이력에 대한 검증은 포함하지 않는다. 첨부 심사기준 기반의 합성 질의를 사용한다.

## 2. 요구사항 대응
- 실사용 상황을 반영한 질의 100건: data/questions_100.json 및 CSV. 25개 상담 유형별 4건. 실제 고객 원문을 수집한 자료가 아닌 합성 초안이다.
- 템플릿 DB: data/templates.json, 30개 대표 질의·응답과 근거 연결. 전문가 검토 전이다.
- 자동 추천 결과: 실행별 recommendations.json에 추천 원문, 상위 3개 ID·유사도·지연시간 기록.
- 수정 없이 활용 가능 여부: A 실무자, B 변리사 또는 상담 경험자의 독립 이진 판정.
- 정량 설문: 문맥·정확성·완결성·활용성·안전성의 1~5점과 성공/실패 및 이유 기록.
- 불일치: A와 B 두 명으로는 다수결이 불가능하므로 협의를 사용한다. 협의 이유·참여자·시각을 남긴다. 합의 실패 시 제3평가자 도입을 별도 승인하거나 미확정 상태로 둔다.
- 합의율: 협의 이전 A·B의 동일 판정 건수/100. 협의 결과로 최초 판정을 덮어쓰지 않는다.

## 3. 모델과 실행 조건
기본 모델은 intfloat/multilingual-e5-small이다. 한국어를 지원하는 다국어 E5 모델이며 별도 학습 또는 한국어 전용 E5-Ko 미세조정 모델로 표시하지 않는다. 시험계획의 ‘E5-Ko’가 한국어 전용 모델을 뜻하면 시험기관과 허용 모델을 확정한 후 --model-id로 승인 모델을 지정해 전체 100건을 다시 실행한다. 다운로드된 모델의 정확한 40자리 커밋 SHA와 파일 해시를 저장한다. 모델의 모델카드·라이선스 및 활용 조건도 승인 시 확인한다.

CPU PyTorch, 최대 길이 512 토큰, query: / passage: 접두어, 정규화 임베딩의 코사인 유사도, top_k=3을 사용한다. 1위 템플릿의 등록 응답 원문을 그대로 추천한다. 차원은 실제 로딩된 모델에서 기록한다. 신뢰할 수 없는 원격 코드는 실행하지 않는다. 모델 오류 시 문자 검색으로 자동 대체하지 않는다.

옵션 llm_select는 E5 상위 3개 중 OpenAI가 ID를 선택하고 해당 템플릿 원문을 그대로 반환한다. 기존 제품의 자유 생성 모드와 동일하다고 주장하지 않는다. API 인증과 기관 허용 여부 확인 후 별도 실행·평가가 필요하다. 기본 시험은 외부 LLM 없는 template_direct이다.

문자 n-gram TF-IDF는 비교용 baseline이며 E5/KoBERT 시험 결과에 포함하지 않는다. 추천 점수는 검색 유사도이지 성공 확률이나 평가자 적합도 점수가 아니다.

## 4. 사전 승인 및 동결
1. 담당 실무자와 변리사가 질문, 기준답변, 템플릿, 근거 페이지를 검토한다. 잘못된 최신 기한·수수료, 경과규정, 모호한 문맥을 수정하고 승인한다.
2. 승인자 성명·역할·일시·서명, 데이터셋과 템플릿 SHA256를 별도 승인 기록에 남긴다. data/approval.example.json을 참고해 data/approval.json을 작성한다. 입력된 이름만으로 승인을 인증하지 않는다.
3. 현 데이터셋은 템플릿과 함께 작성되었으므로 독립된 미사용 시험셋이라고 주장하지 않는다. 최종 성적 주장에는 운영 분포를 확인한 추가 독립 질의 100건 또는 기관이 승인한 별도 홀드아웃을 마련한다. 실제 질의의 개인정보는 익명화한다.
4. 평가용 질의는 추천 로직·템플릿·프롬프트 조정에 사용하지 않는다. 현 초안에서 발견된 오류를 개선할 경우 신규 버전·신규 독립 시험셋으로 평가한다. 이미 공개한 100건에서 점수를 올린 결과는 개발 검증으로 표시한다.
5. 합격 기준이 제공되지 않았으므로 임의로 90%, 95% 등의 목표나 합격을 설정하지 않는다. 요구 성능, 시험 모드, 표본 구성과 불일치 절차를 시험기관과 사전에 확정한다.

## 5. 실행 절차
저장소 /workspace/test-nlu에서 /workspace/nlu-venv/bin/python을 사용한다. scripts/install.sh로 의존성을 설치하고 scripts/download_model.py로 모델을 검증·보관한다.

python -m nlu.cli run --backend e5 --model-path /workspace/nlu-model

생성된 artifacts/runs/<run-id>를 실행 단위로 보관한다. 초기 로딩·인덱싱은 개별 질의 지연시간에 포함되지 않는다. 100건 모두 실행되었는지, case_id 누락·중복이 없는지, 후보와 추천 원문이 템플릿 DB에 있는지 확인한다. 실패한 요청을 임의로 정상 답변으로 채우지 않는다. 환경 실패는 원인을 조치하고 신규 실행ID로 다시 실행하며 기존 실패 로그를 보존한다.

python scripts/build_deliverables.py --run-dir artifacts/runs/<run-id> --out artifacts/review_package

A와 B에게 각각 평가자A_실평가.xlsx, 평가자B_실평가.xlsx를 배포한다. 질의·추천 원문·근거를 제공하되 상대 평가나 모의평가, 기대 템플릿 ID·검색 점수를 먼저 보여주지 않는다. 평가자들은 정량 설문 5개, 성공/실패, 근거, 성명·자격·일시를 직접 입력한다.

python scripts/collect_ratings.py --run-dir artifacts/runs/<run-id> --a <A.xlsx> --b <B.xlsx> --resolution <협의.csv> --output <ratings.csv>
python -m nlu.cli score --run-dir artifacts/runs/<run-id> --ratings <ratings.csv> --output <metrics.json>

collect_ratings는 파일 실행ID·추천원문 무결성, 100건 완전성, 설문 값, 평가근거와 이름 등을 확인한다. 서명·자격·실제 심사행위의 진위 확인은 시험 담당자의 책임이며 자동 검증이 대체하지 않는다. 원본 서명 자료와 협의 회의록을 별도 보관한다.

## 6. 지표와 산식
전체 추천 응답 수 N=100을 고정한다. 성공 S, 실패 F가 최종 확정되어 S+F=100일 때만 적합도를 확정한다.

적합도(%) = S / 100 × 100
합의율(%) = 최초 A=B인 건수 / 100 × 100

평가 미완료 또는 협의 미해결 건이 있으면 최종 적합도는 미산출이다. 스킵·미실행 건을 분모에서 빼고 점수를 높이지 않는다. 협의로 확정된 건수와 최초 일치 건수를 구분해 보고한다. Cohen’s κ와 Wilson 95% 구간은 보조 진단이며 합격 여부를 결정하지 않는다. κ가 정의되지 않는 경우 null로 표시한다. 표본이 합성·편의 표본이므로 신뢰구간을 운영 모집단의 보장으로 해석하지 않는다.

## 7. 표준 표시의 범위
ISO/IEC 25023:2016, ‘8.2.2 Functional correctness measures / FCr-1-G’는 사용자가 제공한 시험 요구문에서 인용한 항목이다. 본 작업에서는 정식 표준 원문을 열람해 절 번호·지표 코드·측정 단위를 검증하지 않았다. 위 백분율 산식은 사용자 시험계획의 정의를 구현한 것으로, ISO 인증 또는 표준이 정한 합격 기준이라고 표시하지 않는다. 시험기관이 표준 원문 및 개별 응답 성공률 적용 타당성을 확인한 뒤 최종 성적서 표기를 확정한다.

## 8. 결과 확정·보관
모델 커밋·파일 해시, 소스 버전, 의존성 잠금, 질의·템플릿·추천 원문 해시, 실행 환경·로그, 독립 평가 원본, 서명 승인서, 불일치 협의 기록, 최종 집계파일을 함께 보관한다. 모델·템플릿·질의·모드 변경 후에는 신규 실행으로 기록한다. 성적서는 시험기관이 자신의 절차에 따라 발행하며 이 저장소의 문서는 제출 준비 자료이다.
